**Status**: Draft

## 1. 🧠 User Scenario Brainstorming (用戶情境腦力激盪)

基於 PRD 定義的目標用戶（對佛法教育感興趣的群體），我們構想了以下關鍵使用情境：

### Scenario A: 通勤族的碎片時間 (The Commuter)
*   **用戶**: 35歲上班族，對佛法有興趣但時間零碎。
*   **情境**: 在捷運上收到 LINE 通知「最新影音」上架。
*   **行為**: 
    1. 點開通知。
    2. 看到感興趣的標題/封面。
    3. **期望**: 能快速知道影片長度、講者是誰，決定是否現在看或標記稍後看。
    4. **潛在痛點**: 如果點進去才發現是 2 小時的長影片且無法背景播放，會立刻跳出。

### Scenario B: 長輩的早課習慣 (The Elder Practitioner)
*   **用戶**: 65歲退休人士，習慣每天早上聽經。
*   **情境**: 想找「最新法寶」裡的電子書來閱讀。
*   **行為**:
    1. 打開 LINE Bot 選單。
    2. 點擊「最新法寶」。
    3. **期望**: 字體要夠大，操作要簡單（不要太多層級），能直接打開 PDF 或閱讀介面。
    4. **潛在痛點**: 如果下載 PDF 流程複雜（如跳轉瀏覽器、需要登入、檔案過大跑不動），會感到挫折。

### Scenario C: 活動分享者 (The Sharer)
*   **用戶**: 佛學社團志工。
*   **情境**: 看到一本很好的新書或影片，想分享給社群群組。
*   **行為**:
    1. 在 Bot 中看到內容。
    2. 想轉發給朋友。
    3. **期望**: 轉發出去的卡片（Flex Message）資訊完整且好看，朋友點開能直接看，不需要重新關注 Bot 才能看（雖然關注是 KPI，但體驗上要順暢）。

## 2. 🚀 UX Optimization Suggestions (最佳化建議)

針對 M0 設計與 M1 核心功能，提出以下具體建議：

### 2.1 Flex Message 卡片設計 (視覺優化)
*   **封面圖 (Hero Image)**: 
    *   **建議**: 確保「最新法寶」書籍封面和「最新影音」縮圖在 Flex Message 中比例統一（建議 1.91:1 或 1:1），避免被裁切。
    *   **細節**: 影片卡片上直接疊加「播放按鈕」圖示與「時長」標籤（如 `15:30`），讓用戶一眼預估時間成本。
*   **資訊層級 (Hierarchy)**:
    *   **標題**: 最顯眼，最多兩行，超過省略。
    *   **副標**: 講者/作者名稱，使用次級顏色（灰色）。
    *   **標籤 (Badges)**: 使用顏色區分「直播中」(紅色)、「新上架」(綠色)、「熱門」(橘色)。

### 2.2 互動流程 (Interaction Flow)
*   **減少跳轉**: 
    *   **現狀**: 點擊連結通常會跳出 LINE 開啟瀏覽器。
    *   **優化**: 盡量使用 LIFF (LINE Front-end Framework) 在 LINE 內部開啟內容，保持沈浸感，減少流失率。特別是「最新影音」，若能嵌入播放器體驗最佳。
*   **PDF 下載優化**:
    *   針對「最新法寶」，若提供 PDF 下載，建議先提供「試閱」或「目錄」預覽，不要讓用戶直接下載大檔案，浪費流量且等待時間過長。

### 2.3 訂閱與推播 (Subscription)
*   **精準推播**: 
    *   **建議**: 在「訂閱最新影音」功能中，增加簡單的分類訂閱（如：依講者、依主題），避免全量推播造成封鎖率上升。
    *   **頻率控制**: 即使有新內容，建議合併推播（如：每日摘要），而不是每上一則就推一次。

## 3. ⚠️ Newbie Pitfalls (新手坑/常見誤區)

*   **誤區 1: "Click Bait" 標題但內容不符**
    *   **後果**: 用戶點進去發現不是想要的，信任度下降。
    *   **解法**: 標題與摘要必須精準描述內容（例如：是「全集」還是「精華短片」）。
*   **誤區 2: 忽略「分享」後的體驗**
    *   **後果**: 用戶分享卡片給朋友，朋友點開卻顯示「請先關注」或 404 錯誤。
    *   **解法**: 確保分享連結帶有 UTM 參數或 Deep Link，若非好友點開，先引導至 Landing Page 預覽內容並鼓勵關注，而不是直接擋在門外。
*   **誤區 3: 字體過小或對比度不足**
    *   **後果**: 長輩用戶看不清楚。
    *   **解法**: Flex Message 內文字體至少 `sm` 或 `md`，重要按鈕使用高對比色。

## 4. 👁️ Visual Flow & Attention (視覺動線問題)

*   **按鈕位置**: 
    *   主要行動（Call to Action，如「立即觀看」、「下載法寶」）應放在卡片最下方或右側，符合拇指熱區。
    *   次要行動（如「查看詳情」、「分享」）可使用較小的按鈕或文字連結。
*   **閱讀順序**:
    *   **Z型動線**: 圖片 -> 標題 -> 摘要 -> 按鈕。確保視覺重心不要亂跳。
*   **狀態回饋**:
    *   點擊按鈕後，若需等待（如讀取資料），必須有 Loading 動畫或文字回饋，LINE Bot 介面容易讓用戶以為沒點到而重複點擊。

## 5. Next Steps (下一步建議)

1.  **Prototype 測試**: 在 M1 開發階段，先用 LINE Bot Designer 做出高保真 Mockup，找 3-5 位目標用戶（包含一位長輩）做簡單的易用性測試。
2.  **LIFF 評估**: 評估是否將「閱讀」與「觀看」體驗透過 LIFF 實作，以提升流暢度。
3.  **數據埋點規劃**: 在 PRD 中補上數據追蹤需求（點擊率、觀看時長、分享數），以便 M3 階段優化。
